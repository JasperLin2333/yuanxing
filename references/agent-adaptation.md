# Agent 接入与分发

## 按能力选择执行路径

元形不内置聊天模型；理解用户意图、编辑文件和执行命令由接入的 Agent 宿主承担。不要再向用户索取模型 API Key，不在原型中添加另一个聊天框。

| 当前能力 | 执行方式 |
| --- | --- |
| 读写文件与运行 Node.js 20+ | 直接编辑用户项目，通过随包 CLI 检查、导出；设计与迭代元形项目时默认用 `open --reuse` 启动或复用可编辑工作台，纯讨论、只读检查及仅导出除外 |
| 可读写文件，但不能执行命令 | 编辑现有页面和编排，交付源文件；明确本轮无法构建或检查，保留可执行命令供有权限的环境继续 |
| 可执行命令，但浏览器不能访问宿主的本机端口 | 在同一执行环境生成离线 HTML，通过宿主产物预览或下载入口交付；不把远程沙箱的 localhost 当作用户电脑 |
| 只能读取资料或对话 | 提供设计与交互调整建议，说明缺少项目写入能力；不声称已经保存、启动或导出 |

首次接入通过实际读取项目、获取 Node 版本或本轮所需的命令结果证明能力；不以安装成功或包文件存在证明宿主已加载 Skill。重新安装、提升权限、联网或打开浏览器须遵守当前用户与宿主授权，Skill 不扩大权限。

所有路径由当前环境解析并正确引用。使用 `<Skill目录>/scripts/yuanxing.mjs`，项目根目录通过 `--root` 传入；不依赖 `pwd` 恰好是 Skill 目录。项目扩展是可选项，只加载本项目明确指定的扩展，不能把某个项目的代码带给其他项目。

## 本机启动与桌面入口

在用户电脑可访问本机端口的环境中，设计阶段使用后台启动命令并带 `--reuse`。仅新启动服务时自动打开一次浏览器；同一工作台已运行时直接复用并返回 URL，不再开页、切换标签或强制刷新，`--project` 也不触发重复开页。这里采用“每次服务启动只自动开页一次”，不把服务运行状态当作浏览器标签仍存在的证明；关闭页面后需要重新打开时，使用不带 `--reuse` 的 `open` 或桌面入口。端口被其他服务占用则保留该服务并提示更换端口，不关闭已有进程。

```sh
node "<Skill目录>/scripts/yuanxing.mjs" open --root "<项目目录>" --reuse
node "<Skill目录>/scripts/yuanxing.mjs" open --workspace "<工作区.json>" --project project-a --reuse
node "<Skill目录>/scripts/yuanxing.mjs" desktop --workspace "<工作区.json>"
```

`open` 保存本机默认启动目标；不带目标参数时使用已配置的工作台。不带 `--reuse` 表示显式打开浏览器，供用户手动打开或重新打开；Agent 日常迭代统一带 `--reuse`，不要另用系统命令补开页面。项目扩展、builder 与 validator 继续按现有命令显式传入；工作区模式从登记读取。`--no-browser` 始终不打开浏览器，可用于启动链路检查；服务已运行但从未开页时也由用户显式打开。原有 `serve` 保留前台运行方式，日常迭代不反复执行 `serve --open`。

用户要求桌面快捷方式时执行 `desktop`，可使用上次 `open` 保存的目标。macOS 创建“元形工作台.app”并注册 `yuanxing://open`；Windows 创建桌面快捷方式并在当前用户下注册同一启动链接。两种入口调用相同的 `open` 命令，双击或点击按钮均不导入离线文件。设置与日志保存在 `~/.yuanxing/`，桌面入口更新前备份已有元形入口；Skill 与 Node 路径变化后重跑 `desktop`。未配置启动目标时先打开一个项目，不擅自扫描或登记其他目录。

离线文件顶栏在“更新说明”与“导出 HTML”之间常驻“打开工作台”，流程画布、需求文档、完整原型共用同一位置；它通过本机已注册的启动器打开工作台，文件继续保持只读。接收者未安装启动器时，需要先让自己的 Agent 安装元形、设置本机项目并创建桌面入口。既有离线文件需要重新导出才有新按钮；文件不携带发送者本机路径或启动令牌。

## 通过对话操作项目

Agent 接到“再建一个项目”“切到某项目继续改”“把这些模块串成完整原型”后，读取已知工作区、对应项目与直接依赖，完成创建、登记、页面修改、控件绑定和导出。只有存在会改变产品含义的歧义才追问。

```sh
node "<Skill目录>/scripts/yuanxing.mjs" workspace list --workspace "<工作区.json>"
node "<Skill目录>/scripts/yuanxing.mjs" workspace add --workspace "<工作区.json>" --root "<项目目录>" --id project-a --name "项目甲"
```

工作区只登记用户指定的项目，登记同一 id 不能改指其他目录。服务为不同项目使用独立 URL、文件保存版本与扩展；切换前保存未提交编辑，失败时留在原项目。每个项目的源与导出留在它自己的目录，发布 Skill 不携带个人项目。

## 按影响验证

- 原型文案、样式和需求正文：核对本轮含义、受影响语法与引用，不运行通用测试库，不为简单页面补测试。
- 修改元形源码（CLI、运行时、数据协议、分发）：`npm test` 与打包脚本只在源码仓库提供，安装包不含 `package.json`、`test/` 和 `scripts/pack.mjs`；维护流程见源码仓库的 `CONTRIBUTING.md`。
- 已通过且未再变化的检查不重跑；交付说明行为与实际证据，不逐条展示日志或把测试总数当作用户验收。
- 只有影响现有分享内容或离线运行代码时才重建该入口。纯 Skill 文字、定位和 CLI 加载优化不自动重建原型或生成各渠道包。

## 分发与版本

维护同一份通用 `SKILL.md`、`scripts/`、`runtime/` 和参考资料。`agents/openai.yaml` 仅提供支持它的宿主使用的展示元数据。市场需要的字段在发布时注入，不在主指令中堆叠每个平台的字段或维护多套运行时。

本机安装与更新使用随包脚本，不直接覆盖已安装目录：

```sh
node scripts/install.mjs --target "<宿主Skills目录>/yuanxing"            # 首次安装，目标已存在时停止
node scripts/install.mjs --target "<宿主Skills目录>/yuanxing" --check    # 只读：列出与源码打包结果及安装记录的差异
node scripts/install.mjs --target "<宿主Skills目录>/yuanxing" --update   # 备份后整体替换
```

安装时在目标根目录写入 `.yuanxing-install.json`，记录版本与各文件摘要，只供更新判断，不进入发布包。`--update` 先在旁边组装新版本，再完整备份原目录并核对，最后整体替换；默认备份到 `~/.yuanxing-backups/`，可用 `--backup <目录>` 指定，不能放在安装目录内或 Skills 目录中被当作同名 Skill。检测到安装后的本地改动，或旧安装没有记录且内容与源码不同时，先输出差异并停止；核对后加 `--force` 才更新，仍会先备份。目标是符号链接时直接维护其源码。

打包脚本 `scripts/pack.mjs` 仅存在于源码仓库，安装包不含；渠道包的构建、字段来源与发布约束见源码仓库的 `CONTRIBUTING.md`。不要把自用项目、绝对本机路径、宿主凭据或端口会话令牌写入发布包。
