# 典型场景示例

每个示例给出用户话术、Agent 的动作与应交付的结果；命令参数以 `help` 为准，路径由当前环境解析。

## 修改已有元形项目的原型

用户：“把订单列表的筛选区加一个‘已取消’状态，对应需求也改一下。”

1. `locate --root <项目> --query 订单列表`，读取返回的页面、编辑源与需求行号。
2. 只改目标页面的真实 DOM 与对应需求段落；保留其他页面、画布位置、连线与批注。
3. 项目含 `artifact/workbench.json` 且属于评审后变更时，`updates add --root <项目> --text "订单筛选新增‘已取消’状态" --node <页面>`。
4. 用 `open --root <项目> --reuse` 或 `open --workspace <工作区.json> --reuse` 启动或复用可编辑入口；首次启动才自动开页，已有工作台不重复打开或强制刷新，也不另行调用系统开页命令。首次给出入口时提示可拖动、加说明和贴图，不做浏览器自动操作或截图。交付改动位置与未检查部分，注明待用户验收。用户只要求导出或不打开时跳过启动。

## 人与 Agent 并行编辑后合并

用户：“我刚在工作台里挪了几个节点，你再加一个‘退款结果’页并连到订单详情。”

1. 先读取当前 `artifact/workbench.json`，原样保存为基线（临时目录），修改一份副本。
2. `add` 加入页面，`connect` 建立连线，或在副本里改画布后用 `apply --root <项目> --base <基线.json> --model <修改后.json>` 合并。
3. 同字段冲突时双方内容都保留，按返回结果处理，不整份覆盖；收口清理临时文件。
4. 交付：新增页面与连线、冲突如何处理。

## 导出离线分享

用户：“导出给领导评审，不要依赖网络。”

1. 确认本轮修改已完成，再统一导出：`export --root <项目> --view review --out <文件.html> [--replace]`；需要原型或文档视图时分别改 `--view prototype|document`。
2. 导出自带结构与资源检查，不需要先重复 `check`；覆盖已有分享前确认它是本项目的生成物。
3. 需要上传 WorkBuddy 预览时核对最终 HTML 小于 50,000,000 字节；超限先查重复资源与编码，不降画质、不删页面。
4. 交付：输出文件路径、实际字节数、包含的视图，注明待用户验收。
