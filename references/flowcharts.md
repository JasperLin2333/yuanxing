# 需求中的流程图

需求有多步骤、条件分支、异步处理或不同处理时机时，用流程图说明主流程；价格、额度等简单规则不强行配图。只表达已确认的触发、判断、分支和结果，沿用现网的部分按用户要求概括，不展开实现细节。

## 绘制与维护

- 简单业务流程默认从左向右排列，按不同触发时机拆成几张小图；复杂流程按可读性选择方向。图放在对应需求章节，正文补充细则，不逐节点重复解释。
- 新图优先用自包含 HTML 内嵌 SVG，直接作为工作台 HTML 节点。SVG 使用 `viewBox="0 0 宽 高"`、原生文字、矩形、菱形和箭头；字体、颜色、线条样式放 SVG 内，避免外部资源、`foreignObject` 和联网绘图库。保持文字可读、分支不交叉；工作台的缩放由共享查看器提供，不在图中重写一套操作。
- HTML 是唯一绘图源；需要在普通 Markdown 中阅读时，从同一 SVG 生成高清 PNG，以相对图片路径插入 PRD。图和正文变化一起更新，不重新截图、不维护内容不同的两张图。已有可编辑绘图源按本次要求保留或迁移，不强行重画。
- HTML 放项目已有页面目录，PNG 放项目已有图片目录；只维护目标图，不把制作说明写入 PRD。入口与源稿导航按项目约定放 README。

从 HTML 生成 PNG 可使用本 Skill 的脚本，复用环境已有的 `@resvg/resvg-js`，或通过 `--renderer <模块目录>` 指定。缺少时可在本次任务的临时目录安装该渲染依赖，完成后清理，不改全局工具配置：

```sh
node "<Skill目录>/scripts/flowchart.mjs" --input "<项目>/artifact/pages/业务流程.html" --output "<项目>/artifact/assets/业务流程.png" --renderer "<可用的resvg模块目录>"
```

默认生成 2 倍 PNG；中文字体缺失时可传 `--font <本机可用的中文字体文件>`。只改变图片阅读尺寸不重做图源、不压低图片质量。

## 原位置嵌入可缩放画布

在 HTML 节点与 PRD 图片之间建立 `source.imageFrames` 对应关系，工作台在图片原位置显示该 HTML 节点，普通 Markdown 仍显示 PNG：

```json
{
  "id":"requirements",
  "type":"source",
  "path":"需求/业务需求.md",
  "imageFrames":{
    "../artifact/assets/业务流程.png":{"node":"business-flow","frameScale":0.8}
  }
}
```

图片路径须与 Markdown 内的图片写法一致，独占一段；`node` 对应现有 HTML 或图片节点。无需把完整 PRD 拆成多份或复制正文；图可同时放在流程画布，保持独立查看。只需要文档嵌入的节点可设置 `canvas:false`。

`frameScale` 控制外框占位，默认 1，可按正文密度先缩小到 0.8；右下角拖动后本地保存，刷新后继续使用。框内的缩小、放大、适应、拖动及触控板手势复用原型查看器，不改变正文占位。离线导出保留相同比例与操作，接收者的临时调整不修改源文档。

已有图只需缩放时，也可直接关联图片节点，不要求先转成 HTML。缺少对应关系的普通图片继续按原方式展示；删除关联节点后回退为原 PNG。
